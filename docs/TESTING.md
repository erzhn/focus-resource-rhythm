# Тестирование

## Unit (Vitest) — реализовано, 44 теста зелёные

Запуск: `npm test`. Покрыто (`src/domain/**/*.test.ts`):

- Расчёт приоритета и объяснение факторов; вклад срочности и просрочки; предупреждения по ресурсам.
- Ручной override приоритета (хранится отдельно, системный сохраняется).
- Блокировка задачи зависимостью (не рекомендуется).
- Ограничение трёх активных результатов + варианты освобождения фокуса.
- Подбор задач в план дня при разном уровне сил; лимит «1 главное + до 2 доп + повторяющиеся».
- Резерв времени 20–30% и удержание бюджета.
- Конфликты временных блоков (пересечения, смежность, минуты пересечения).
- Повторения: дни недели, последняя пятница/N-й день, произвольный интервал, исключение экземпляра,
  дата окончания.
- Помощник формулировки (детерминированный, без LLM).

## Интеграционные (план)

Требуют поднятой базы (Supabase локально/облако). В текущей среде нет Docker, поэтому запуск
отложен; сценарии:

- Регистрация/вход; проверка **RLS** (нельзя прочитать чужие данные).
- CRUD сфер, целей, проектов, этапов, задач, событий.
- План/факт ресурсов; утренний план и вечерний итог; создание уведомлений.
- Календарные адаптеры через mock HTTP-сервер; повторная доставка webhook не создаёт дубль.

## E2E (Playwright, план)

Сценарии из ТЗ §21: регистрация→настройка→пустой «Сегодня»; создание задачи→вопрос о формулировке→
рекомендация; три активных результата и защита при четвёртом; утренняя проверка→редактирование→
подтверждение; drag-and-drop→конфликт→решение; частичное выполнение→вечернее решение; повторение и
изменение одного экземпляра; обновление статистики; мобильная ширина без поломок; принятие/отклонение
смоделированного внешнего изменения. Внешние API в CI не вызываются — только контрактные mock-и.

## Ручная проверка в этой сессии

- `npm run lint`, `npm run typecheck`, `npm test`, `npm run build` — проходят.
- Dev-сервер: экран «Сегодня» рендерит реальный план и объяснения приоритета; на «Все планы»
  подтверждён отказ добавить 4-й активный результат с корректным сообщением.
