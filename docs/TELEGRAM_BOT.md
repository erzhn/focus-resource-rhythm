# Telegram-бот: расходы из чата

Бот позволяет записывать траты, не открывая сайт: пишете «Такси 250» — запись
появляется в приложении. Вечером приходит итог дня.

Код бота готов и задеплоен. Остаётся то, что может сделать только владелец
аккаунта: создать бота и выдать приложению его токен.

## 1. Создать бота (2 минуты)

1. В Telegram откройте [@BotFather](https://t.me/BotFather).
2. `/newbot` → имя (любое) → username (должен заканчиваться на `bot`).
3. BotFather пришлёт токен вида `1234567890:AA...`. Это пароль от бота —
   никому не показывайте и не кладите в репозиторий.

## 2. Сгенерировать секрет вебхука

Он нужен, чтобы вебхук принимал запросы только от Telegram, а не от любого,
кто узнал адрес:

```bash
node -e "console.log(require('crypto').randomBytes(24).toString('hex'))"
```

## 3. Добавить переменные в Vercel

Project → Settings → Environment Variables → Production:

| Переменная | Значение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | токен от BotFather |
| `TELEGRAM_WEBHOOK_SECRET` | строка из шага 2 |
| `NEXT_PUBLIC_TELEGRAM_BOT_NAME` | username бота **без @** |

После добавления — Redeploy: переменные подхватываются только новой сборкой.

## 4. Зарегистрировать вебхук

Одной командой (те же переменные должны быть в `.env.local` или в окружении):

```bash
npm run telegram:setup -- https://focus-resource-rhythm.vercel.app
```

Скрипт проверит токен, пропишет вебхук с секретом, заведёт меню команд и
покажет состояние доставки. Повторяйте его после смены домена или секрета.

## 5. Привязать свой чат

Приложение → Настройки → Telegram-бот → «Получить код» → отправьте боту
`/start КОД`. Код одноразовый и живёт 15 минут.

Привязка нужна потому, что Telegram сообщает боту только `chat_id` — кто это,
бот сам не знает и угадывать не должен.

## Что умеет

| Сообщение | Что делает |
| --- | --- |
| `Такси 250` | записывает расход, категория определяется сама |
| несколько строк сразу | каждая строка — отдельная запись |
| `Зарплата 20000` | записывает доход |
| `/today` | итог за сегодня: расходы, бюджет, остаток |
| `/month` | итог за месяц по категориям |
| `/undo` | удаляет последнюю запись |
| `/help` | подсказка |

### Торговля

Торговые действия выполняются **только по явной команде**. Свободный текст
по-прежнему означает расход — это не изменилось.

| Команда | Что делает |
| --- | --- |
| `/in XAUUSD buy 4650 sl 4632 tp 4700 0.01` | проверяет план и записывает вход |
| `/log …` | записывает совершённую сделку, в том числе с нарушениями |
| `/open` | открытые позиции |
| `/out 4700` | закрывает остаток |
| `/partial 0.01 4680` | закрывает часть |
| `/stop 4650` | переносит стоп (исходный риск не меняется) |
| `/balance`, `/account` | счёт и его баланс |

Команды `/out`, `/partial` и `/stop` работают, когда открыта одна позиция.
Если открыто несколько, бот не угадывает, какую вы имели в виду, и отправляет
в приложение.

### Надёжность доставки

Входящие обновления складываются в очередь `telegram_updates` с состоянием и
арендой. Повторная доставка от Telegram не создаёт вторую операцию, а
оборвавшаяся обработка не теряется: её подберёт `/api/telegram/process`.

Исходящие идут через `notification_outbox` с ключом события. Поэтому повторный
запуск планировщика не присылает один и тот же отчёт дважды.

Вечерний отчёт уходит по расписанию Vercel Cron — эндпоинт
`/api/telegram/daily-report`, защищённый `CRON_SECRET`. Очередь дообрабатывает
`/api/telegram/process` (тот же секрет).

## Если что-то не работает

- **Бот молчит.** `npm run telegram:setup -- <домен>` покажет
  `last_error_message` от Telegram — обычно это неверный домен или 401 из-за
  разошедшегося `TELEGRAM_WEBHOOK_SECRET`.
- **«Сначала привяжите аккаунт».** Код истёк или был использован — получите новый.
- **Переменные добавлены, а бот не настроен.** Нужен Redeploy: Vercel не
  применяет новые переменные к уже собранному деплою.

Требуется миграция `..._telegram.sql` (применена).
