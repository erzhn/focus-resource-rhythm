# Архитектура

## Слои

1. **Домен** (`src/domain/**`) — чистые функции без React/БД: приоритет, зоны фокуса, повторения,
   ресурсы/резерв, конфликты расписания, построение плана дня, помощник формулировки. Полностью
   тестируется Vitest. Веса и правила методики — в конфигах (`priority/weights.ts`, `config/app.ts`).
2. **Данные** (`src/lib`) — форматирование (TZ/деньги), определение режима (`env.ts`) и провайдер
   состояния. Сейчас активен демо-провайдер (`lib/demo/store.tsx`) с данными в памяти; интерфейс
   стора спроектирован под замену на Supabase-провайдер без изменения экранов.
3. **Представление** (`src/app`, `src/components`) — экраны App Router и переиспользуемые компоненты.
   Доменная логика в компоненты не «размазана»: они вызывают функции домена и рендерят результат.
4. **Хранилище** (`supabase/migrations`) — PostgreSQL со строгой изоляцией по `user_id` и RLS.

## Модульность

Предметные модули: `auth, planning, tasks, priorities (priority), resources, recurrence, calendar
(schedule), integrations/*, reviews, notifications, analytics`. Внешние календари подключаются через
единый интерфейс `CalendarProvider` (Этап 6), чтобы Google и Microsoft не дублировали доменную логику.

## Режимы работы

`isSupabaseConfigured` (наличие `NEXT_PUBLIC_SUPABASE_URL` и anon key) переключает приложение между
реальным хранением и демо-режимом. Демо-режим явно помечается в UI и предназначен только для
локального просмотра без ключей.

## Время и деньги

- Метки времени — UTC (`timestamptz`); часовой пояс пользователя — отдельная настройка; преобразование
  на границе UI (`lib/format.ts`).
- Деньги в домене — целые минорные единицы (тыйын); в БД — `numeric(14,2)`.

## Безопасность

RLS на всех пользовательских таблицах; service-role ключ — только сервер; OAuth refresh-токены —
зашифрованы ключом окружения и не покидают сервер; журналируемые объяснения приоритета и синхронизации.
