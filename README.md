## О продукте

Персональная система планирования, построенная вокруг методики **«Фокус — Ресурс — Ритм»**:

| Принцип | Суть |
|---|---|
| **Фокус** | Не больше трёх активных крупных результатов. Зоны «Сейчас / Следом / Позже / Отказ». |
| **Ресурс** | Планируется не только время, но и силы (1–5) и деньги (лимиты, предупреждения). |
| **Ритм** | Горизонты год → 90 дней → месяц → неделя → день. Утренний план и вечерний итог. |

Первая версия — для одного владельца, но данные с самого начала изолированы по `user_id` (RLS),
чтобы систему можно было безопасно сделать многопользовательской.

> **Режимы работы.** С ключами Supabase приложение хранит данные в PostgreSQL с RLS и авторизацией.
> Без ключей запускается **демо-режим** с данными в памяти — он явно помечен в интерфейсе и нужен
> только для локального просмотра.

## Возможности

### Фокус и задачи
- Зоны «Сейчас / Следом / Позже / Отказ» и **лимит трёх активных результатов** с вариантами
  освобождения фокуса (завершить / приостановить / перенести / отменить).
- **Быстрое добавление задачи** с любого экрана + обязательный вопрос «Нужно ли помочь
  сформулировать?» и шаблонный помощник (работает без внешнего ИИ).
- **Объяснимый приоритет 0–100** с разбором факторов человеческим языком; ручной приоритет
  хранится отдельно от системной рекомендации.

### Ритм: день и неделя
- **Сегодня** — утренняя проверка (силы, время), одно главное дело + до двух дополнительных +
  обязательные повторяющиеся, резерв времени 25%, предупреждения о перегрузке и нехватке сил,
  подтверждение плана дня.
- **Вечерний итог** — статусы, перенос с *обязательной причиной*, разделение, отмена, уровень сил,
  вывод дня.
- **Еженедельная сверка** — счётчики, решения по крупным результатам с причиной, до трёх
  результатов следующей недели.

### Календарь и ресурсы
- **Календарь** — режимы день / неделя / месяц / год; неделя с **drag-and-drop** (и клавиатурной
  альтернативой ← →), пересчётом нагрузки и пометкой перегрузки/конфликтов.
- **Ресурсы** — план/факт и лимиты времени, сил и денег (валюта `KGS`).
- **Уведомления**, ведущие к конкретному действию.

### AI-ассистент
- **Чат-ассистент** — «поговорить обо всём» и помощь по методике; видит краткий контекст планирования
  (план дня, активные результаты, ресурсы), отвечает потоково. Провайдер выбирается автоматически
  (бесплатные — в приоритете) или через `ASSISTANT_PROVIDER`:
  - **Ollama** — бесплатно и локально (данные не покидают ПК): `ollama run llama3.2`;
  - **Google Gemini** / **Groq** — бесплатные тарифы (нужен бесплатный ключ);
  - **Claude (Anthropic)** — платно, но самое качественное.
  Ключи только на сервере. Без настройки приложение работает как обычно.

### Инфраструктура
- **Двусторонняя синхронизация календарей** Google и Microsoft: единый интерфейс `CalendarProvider`,
  OAuth со `state` + PKCE, шифрование refresh-токенов (AES-256-GCM), разрешение конфликтов
  «было/стало» (чистые функции с тестами). Активируется при добавлении OAuth-ключей.
- **Supabase Auth** (email/пароль) + защита маршрутов, полная схема PostgreSQL (26 таблиц) с RLS.
- Адаптивно (375 / 768 / 1440 px), доступность, светлая/тёмная тема.

## Быстрый старт (демо-режим)

Без базы и ключей — данные в памяти:

```bash
npm install
npm run dev
```

Откройте <http://localhost:3000>. В интерфейсе виден баннер «Демо-режим».

> Требования: Node.js 20+ (проверено на 24), npm 10+. Windows PowerShell поддерживается,
> пути не захардкожены.

## Полный запуск с Supabase

1. **Установить зависимости**
   ```bash
   npm install
   ```
2. **Создать проект Supabase** — облако (<https://supabase.com>) или локально (нужен Docker):
   ```bash
   npx supabase start
   ```
3. **Применить миграции** (поднимают всю схему и RLS на чистой базе):
   ```bash
   npx supabase db push
   ```
4. **Загрузить демонстрационный seed** (не для production; сначала зарегистрируйте пользователя):
   ```bash
   npx supabase db execute --file supabase/seed.sql
   ```
5. **Заполнить `.env.local`** — скопируйте из `.env.example` и подставьте значения.
6. **Запустить**
   ```bash
   npm run dev
   ```

## Переменные окружения

Полный список с пояснениями — в [`.env.example`](.env.example). Ключевые:

| Переменная | Назначение | Область |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | URL проекта Supabase | клиент |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Публичный anon-ключ | клиент |
| `SUPABASE_SERVICE_ROLE_KEY` | Сервисный ключ | **только сервер** |
| `TOKEN_ENCRYPTION_KEY` | 32-байтовый ключ (base64) для шифрования OAuth-токенов | **только сервер** |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | OAuth Google Calendar | сервер |
| `MICROSOFT_CLIENT_ID` / `MICROSOFT_CLIENT_SECRET` | OAuth Microsoft Graph | сервер |
| `ASSISTANT_PROVIDER` | Провайдер ассистента: `ollama`/`gemini`/`groq`/`anthropic` (авто, если пусто) | сервер |
| `OLLAMA_MODEL` | Локальная модель Ollama (бесплатно), по умолчанию `llama3.2` | сервер |
| `GEMINI_API_KEY` / `GROQ_API_KEY` | Ключи бесплатных тарифов ассистента | **только сервер** |
| `ANTHROPIC_API_KEY` | Ключ Claude (платно) | **только сервер** |
| `APP_BASE_URL` | Публичный URL для webhook-ов | сервер |

> Секреты в репозиторий не коммитятся. Service-role ключ никогда не попадает в клиентский бандл;
> refresh-токены шифруются и не логируются.

## Интеграции календарей (OAuth)

### Google
1. Google Cloud Console → OAuth 2.0 Client (Web).
2. Redirect URI: `http://localhost:3000/api/integrations/google/callback`.
3. Включить Google Calendar API, минимальные scopes (события).
4. Значения — в `.env.local`.

### Microsoft
1. Azure Portal → App registrations → новый клиент.
2. Redirect URI: `http://localhost:3000/api/integrations/microsoft/callback`.
3. Разрешения Microsoft Graph (`Calendars.ReadWrite`), delta query + change notifications.

### Webhook-и
Push-уведомления требуют публичного HTTPS endpoint. Локально используйте туннель (например `ngrok`)
и укажите `APP_BASE_URL`. Как резерв работает периодическая фоновая синхронизация — webhook не
является единственным механизмом. Подробности потоков и разрешения конфликтов — в
[docs/CALENDAR_SYNC.md](docs/CALENDAR_SYNC.md).

## Устранение типичных ошибок

- **Пусто после перезагрузки** — вы в демо-режиме (данные в памяти). Подключите Supabase.
- **RLS «нет доступа»** — запрос должен идти от аутентифицированного пользователя; политики
  разрешают только свои записи (`auth.uid() = user_id`).
- **Кириллица «квадратиками»** — шрифт Geist без кириллицы, используется системный fallback; норма.
- **Кнопка «Подключить» вернула в настройки** — не заданы OAuth-ключи; добавьте их в `.env.local`.
